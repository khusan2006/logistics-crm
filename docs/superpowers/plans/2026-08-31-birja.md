# Birja — kelishuvlar va yuklar

Until now every load came from Iran: a kelishuv is struck with a hamkor there, and
its yuklar drive the Eron → O'zbekiston road. Some goods are now bought **on the
birja (exchange) inside Uzbekistan** instead. Those purchases need their own two
screens — **Birja kelishuvlar** and **Birja yuklar** — while everything downstream
(ombor, sotuvlar, kassa, qarzlar, hisobotlar) stays one set of books.

## The shape

Birja rows are ordinary `Contract` and `Shipment` rows. Nothing new is modelled,
because "others will be together" only holds if a birja load IS a yuk: the ombor
reads `arrived_lots()`, FIFO draws from `ShipmentLine`, a sotuv attaches to a lot.
A second pair of models would have meant a second warehouse.

What separates them is **who the kelishuv is with**: a singleton `Partner` flagged
`is_birja`. That one decision buys the codes for free — `Contract.save()` already
slugifies the hamkor's name and counts on `Partner.code_counter`, so a kelishuv
against the "Birja" hamkor mints `birja-1`, `birja-2`, … exactly the way
`sobir-3` is minted today. No nullable FK, no second counter, no parsing.

The Birja hamkor is created lazily (`birja_partner()`), never in a migration:
`wipe_business_data()` deletes every Partner, so a migration-seeded row would
vanish on the next `load_starting_data` / `import_prototype`.

## Statuses

`ShipmentStatus` gains a `scope` — `hamkor` (Eron), `birja`, or `umumiy` (both).
The six existing rows become `hamkor`, except the arrival row, which becomes
`umumiy`: reaching it is what turns a yuk into an ombor loti, and that mechanic
must stay identical for both pipelines (`ShipmentStatus.save()` still allows
exactly one arrival row app-wide).

Placeholder birja chain, to be renamed by the operator once the real one is known:

1. Sotib olindi
2. Yuklandi
3. Yetkazilmoqda
4. *(Omborga yetib keldi — the shared arrival row)*

`name` stops being globally unique and becomes unique **per scope**, so a birja
status may later be renamed "Yo'lda" without colliding with the Eron one. The
arrival row is pushed to a high `order` so it sorts last in both chains.

## What a birja yuk does not have

- **QR kod** — handed to drivers leaving Eron. Field and column dropped.
- **Bojxonachi / bojxona** — the goods never cross a border. `customs_pending`
  and its SQL twin `customs_pending_loads()` both exclude birja loads, or every
  arrived birja lot would sit in "Bojxona to'lanmagan" forever.
- Route is `Birja → O'zbekiston` rather than `Eron → O'zbekiston`.

Logist, haydovchi, transport and avans stay: a birja load still moves by truck.

## Steps

1. `Partner.is_birja`, `birja_partner()`, `Contract.is_birja`, `Shipment.is_birja`.
2. `ShipmentStatus.scope` + `for_kind()`; migration scopes the six, seeds three.
3. `customs_pending` / `customs_pending_loads()` exclude birja.
4. `_filter_contracts` / `_filter_shipments` take a `birja` flag; the list views,
   the create views and the Excel buttons pass it. Edit/delete stay shared and
   read the kind off the row.
5. URLs: `birja/kelishuvlar/`, `birja/yuklar/` (+ `new/`, `export.xlsx`) —
   the same views registered with `{"birja": True}`.
6. Templates parameterised by context (title, create url), not copied.
7. Sidebar "Birja" group; Holatlar page grouped by scope.
8. `shipment_detail.html` drops the QR block for a birja yuk, and `shipment_detail`
   / `shipment_driver_edit` turn a tarjimon away from one — a role that can reach
   no birja list must not reach a birja row by typing its number.
9. `tests/test_birja.py`.

## Valyuta

Nothing new. A birja kelishuv goes through the app's existing dual-currency
machinery — `convert_pair` stores both sides with the TYPED one exact, `own_side`
decides which is read, and the picker freezes once money or goods are on it. All
`birja=True` does is start the picker on so'm, which is a default and not a rule.

One display bug surfaced while checking it, and it was never about birja: the
yuklar list drew **Qiymati** with `money_both`, which always led with the dollar.
The goods on a truck are priced in exactly one currency — their kelishuv's — so
that put a figure nobody agreed to at the front of every so'm load's row, birja
and hamkor alike. `money_both` now takes an optional currency and swaps the sides;
the two Qiymati cells pass it. A truck's **Xarajat** deliberately does not — a
so'm transport bill beside a dollar bojxona has no agreed side, so the app's
canonical dollar stays the honest headline there.

## Assumptions

- One counterparty for every birja purchase. If a named broker turns out to
  matter, the singleton becomes a real Partner FK — a small change from here.
- The new pages are admin-only. A tarjimon's job is the Eron road.
- Birja kelishuvlar default to so'm, but the currency is still a choice.
- Hamkor to'lovlari, ombor, sotuvlar, kassa and hisobotlar stay shared.
